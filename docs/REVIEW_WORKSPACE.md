# Review Workspace (Phase 4)

## Purpose

This workspace is a narrow, internal review tool for ACE Services. It allows a reviewer to select a project, inspect the deterministic contractor matches generated by the Phase 2 engine, review the evidence, and approve/reject/skip each match without sending emails or invoking external providers.

## Current implementation

This is a local, developer-safe MVP. It does not implement customer-facing CRM, outreach automation, AI, or external data integrations.

## User workflow

1. Open the project list.
2. Select a project.
3. Review the overall match summary.
4. Inspect a match and its persisted evidence.
5. Choose APPROVE, REJECT, or SKIP.
6. Refresh the list to confirm the persisted review state.

## Frontend architecture

There is no existing frontend in the repository, so the Phase 4 workspace uses the smallest viable stack consistent with the project: a lightweight FastAPI app serves the review interface and exposes the required backend endpoints.

The UI is intentionally read-only with respect to matching logic. It never recalculates scores, geography, confidence, or trade overlap. All scoring and evidence come from persisted Phase 2/Phase 3 backend data.

## API interaction

The app exposes project and match endpoints that the UI consumes directly.

Current routes:
- GET /projects
- GET /projects/{project_id}
- GET /projects/{project_id}/matches
- GET /matches/{match_id}
- POST /matches/{match_id}/review
- POST /projects/{project_id}/matches/generate

## Review actions

The review action route validates IDs and statuses server-side. It performs the Phase 3 review workflow and stores audit records. Approval, rejection, and skip are all local review outcomes only.

No email is sent from this workflow.

## Match generation

Generation calls the existing backend deterministic service and persists rows using the current project/contractor schema. It does not duplicate scoring logic in the client.

## Error handling

The workspace displays clear, human-readable messages for missing projects, invalid IDs, API failures, and invalid transitions while avoiding exposing stack traces or database details.

## Current limitations

- No authentication layer
- No production deployment setup
- No real outreach or email sending
- No AI or ML features
- No external enrichment or paid APIs
- No mobile app UI

## Future

Future phases may add richer filtering, routing, authentication, and automated outreach after the deterministic review workflow is stable and approved.
