# Email Safety — ACE Services

This document defines policies and technical controls to prevent unsafe or unapproved outreach.

## High-level policy
- No automated sending without explicit human approval for the first 3 months of operation.
- System must enforce suppression lists (global and per-campaign).
- Provide idempotency to prevent duplicate sends.
- All emails generated by LLMs must pass grounding and hallucination checks and be approved by an operator before sending.

## Send workflow (contract)
1. `compose_email` (LLM or template) -> stores `emails` record with `send_state=draft` and `idempotency_key`.
2. Operator reviews `draft` in UI and sets `send_state=approved` or requests edits.
3. `send_email` job reads approved drafts, checks suppression lists, checks `idempotency_key`, and enqueues to provider adapter with `request_id`.
4. Provider adapter attempts send; upon provider-ack, set `send_state=sent` and record `provider_message_id`.
5. Webhook events update `send_state` to `delivered`, `bounced`, etc.

## Guardrails
- Idempotency: `emails` table must include `idempotency_key` and database uniqueness to prevent duplicates. If provider doesn't support idempotency, application must dedupe.
- Suppression lists: global suppression table; campaign-level overrides must be explicit and auditable.
- Approval: emails must have `approved_by` and `approved_at` fields for audit.
- Human-in-the-loop: enforce UI approval via backend check before any send job executes.
- Rate limits: global send caps per hour/day, and per-provider throttles.

## Template safety checks
- Verify `claims_used` in LLM output map to canonical DB sources.
- For each email run automated checks:
  - Spammy language heuristics
  - Presence of re-used/mismatched contact data
  - Contains PII beyond allowed fields
  - Company identity misrepresentation
- If any check fails, mark `send_state=needs_review`.

## Webhooks & Bounce handling
- Providers must forward bounce/hard-failure webhooks; map to `bounced` and link to `contact_id`.
- On permanent bounce, add to suppression list and mark `contact.unreliable=true`.

## Safe Defaults
- Default `from` address must be a monitored inbox with human operators.
- Include easy unsubscribe link and legal footer where required by jurisdiction.

## Tests
- Unit tests for idempotency and suppression logic.
- Integration tests simulating provider webhooks including duplicates.

## Operational runbooks
- Manual rollback: how to cancel queued sends when campaign is paused.
- Incident response: for mass bounces or complaints, steps to pause campaign and notify stakeholders.

Implement these controls in documentation first, then in code when signoff is given.
